## 1. Performance Requirements

| ID | Requirement | Target |
|----|-------------|--------|
| NFR-P-01 | Page load time (Time to Interactive) for all content pages | ≤ 2 seconds on a 10 Mbps connection |
| NFR-P-02 | Search results must return within | 500 ms |
| NFR-P-03 | AI score report must be available after session end | ≤ 60 seconds |
| NFR-P-04 | Resume parsing must complete | ≤ 10 seconds after upload |
| NFR-P-05 | WebRTC session connection time (both parties joined → call established) | ≤ 10 seconds |
| NFR-P-06 | Session recording upload (post-session) | Asynchronous — does not block the score report display |
| NFR-P-07 | Email notifications (booking confirmation, reminders) | Delivered within 2 minutes |

| ID | Requirement | Target |

| NFR-A-01 | Platform uptime SLA | ≥ 99.5% monthly (excluding scheduled maintenance) |

## 4. Security Requirements

| ID | Requirement | Detail |
|----|-------------|--------|
| NFR-SEC-01 | All data in transit shall be encrypted | TLS 1.2 minimum; TLS 1.3 preferred |
| NFR-SEC-02 | All data at rest shall be encrypted | AES-256 for video/audio files and database fields containing PII |
| NFR-SEC-03 | Authentication tokens shall be short-lived | JWT access tokens: 15-minute expiry; refresh tokens: 30-day expiry with rotation |
| NFR-SEC-04 | Password storage | bcrypt with minimum work factor of 12; no plaintext passwords stored |
| NFR-SEC-05 | Role-based access control (RBAC) | Enforced at API layer — each endpoint validates the caller's role before processing |
| NFR-SEC-06 | Input validation | All user inputs validated and sanitized server-side; parameterized queries for all DB operations |
| NFR-SEC-07 | File upload security | Uploaded files (resumes, avatars) scanned for malware; MIME type validation enforced |
| NFR-SEC-08 | Rate limiting | Authentication endpoints: max 10 failed attempts per 15 minutes per IP; API: 1000 req/min per authenticated user |
| NFR-SEC-09 | Security headers | HTTPS-only (HSTS), Content-Security-Policy, X-Frame-Options: DENY on all responses |
| NFR-SEC-10 | Dependency vulnerability scanning | Automated scan on every build; critical vulnerabilities block deployment |

## 5. Privacy & Compliance Requirements

| ID | Requirement | Detail |
|----|-------------|--------|
| NFR-PRV-01 | GDPR compliance | Platform must comply with GDPR for EU users: lawful basis for processing, right to access, right to erasure, data portability |
| NFR-PRV-02 | CCPA compliance | Platform must comply with CCPA for California users: right to know, right to delete, opt-out of data sale |
| NFR-PRV-03 | Recording consent | Both parties must explicitly consent via an in-session dialog before recording begins; consent is logged with timestamp and user ID |
| NFR-PRV-04 | Data retention policy | Session recordings retained for 90 days by default; user can delete at any time; auto-deletion job runs nightly |
| NFR-PRV-05 | Privacy policy | A clear, user-readable privacy policy must be accessible from all pages; must document what data is collected, how it is used, and retention periods |
| NFR-PRV-06 | Data deletion on account close | Deleting an account triggers deletion of all PII, recordings, and transcripts within 30 days |
| NFR-PRV-07 | Third-party data sharing | No candidate PII or recordings shall be shared with third-party AI providers without explicit consent and a Data Processing Agreement in place |
| NFR-PRV-08 | Audit logging | All admin actions (account suspension, content changes) and consent events are logged immutably for 12 months |

## 6. Accessibility Requirements

| ID | Requirement | Detail |
|----|-------------|--------|
| NFR-ACC-01 | WCAG 2.1 AA compliance | All user-facing pages must meet WCAG 2.1 Level AA |
| NFR-ACC-02 | Keyboard navigation | All interactive elements (buttons, forms, modals, dropdowns) must be fully operable via keyboard alone |
| NFR-ACC-03 | Screen reader support | All UI components must include appropriate ARIA labels; dynamic content updates must use ARIA live regions |
| NFR-ACC-04 | Color contrast | Minimum contrast ratio 4.5:1 for normal text; 3:1 for large text |
| NFR-ACC-05 | Video captions | All video tutorials must include closed captions (auto-generated + reviewed) |
| NFR-ACC-06 | Focus indicators | All interactive elements must have visible focus indicators; default browser focus ring must not be removed without a styled replacement |

## 7. Usability & Compatibility Requirements

| ID | Requirement | Detail |
|----|-------------|--------|
| NFR-UX-01 | Browser support | Chrome 110+, Firefox 110+, Safari 16+, Edge 110+; no IE support |
| NFR-UX-02 | Responsive design | All pages must render correctly on: mobile (≥360px), tablet (≥768px), and desktop (≥1280px) |
| NFR-UX-03 | WebRTC compatibility | WebRTC sessions must function on Chrome, Firefox, and Edge without plugins |
| NFR-UX-04 | PWA capability | The platform shall be installable as a PWA on mobile devices; core content pages shall be accessible offline |
| NFR-UX-05 | Error states | All error states (network failure, server error, permission denied) display a user-friendly message with a suggested next action |

## 8. Observability & Maintainability Requirements

| ID | Requirement | Detail |
|----|-------------|--------|
| NFR-OPS-01 | Structured logging | All services emit structured logs (JSON) with correlation IDs for request tracing |
| NFR-OPS-02 | Metrics & alerting | Core metrics monitored: API error rate, session failure rate, STT processing latency, video upload success rate |
| NFR-OPS-03 | Uptime alerting | On-call alerting triggered when error rate > 1% over 5 minutes or uptime falls below SLA threshold |
| NFR-OPS-04 | CI/CD pipeline | All code changes go through automated linting, unit tests, and integration tests before deployment |
| NFR-OPS-05 | Feature flags | New features deployable behind feature flags to support gradual rollout and instant rollback |
