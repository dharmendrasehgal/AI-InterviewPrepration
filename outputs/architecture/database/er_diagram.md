## Entity Relationship Summary

| Relationship | Cardinality | Notes |
|-------------|-------------|-------|
| users → candidate_profiles | 1:1 | Created on first profile save |
| users → expert_profiles | 1:1 | Created on expert registration |
| expert_profiles → expert_availability | 1:M | Many availability slots per expert |
| expert_availability → live_sessions | 1:1 | Slot is locked when booked |
| users (candidate) → live_sessions | 1:M | Candidate books many sessions |
| expert_profiles → live_sessions | 1:M | Expert receives many bookings |
| live_sessions → rubric_evaluations | 1:1 | One rubric per live session |
| users (candidate) → mock_sessions | 1:M | Candidate runs many AI sessions |
| mock_sessions → session_responses | 1:M | One response blob per question |
| questions → session_responses | 1:M | Question used in many responses |
| questions → question_answers | 1:M | Multiple sample answers per question |
| users → candidate_bookmarks | M:M (via junction) | Many questions bookmarked |
| users → consent_log | 1:M | Every consent event logged |
| users → audit_log | 1:M | Every admin action logged |
