## 2. Routing & Auth Guards

### Route Protection Pattern

```typescript
// app/(candidate)/layout.tsx
import { redirect } from 'next/navigation'
import { getServerSession } from '@/lib/auth/server'

export default async function CandidateLayout({ children }) {
  const session = await getServerSession()
  if (!session) redirect('/login')
  if (session.role !== 'candidate') redirect('/unauthorized')
  return <CandidateShell>{children}</CandidateShell>
}
```

### Route Groups by Role

| Route Group | Roles Allowed | Auth Method |
|-------------|--------------|-------------|
| `(public)` | Anyone | None |
| `(candidate)` | candidate | Server-side session check |
| `(expert)` | expert | Server-side session check |
| `(admin)` | admin | Server-side session check + admin scope claim |

## 3. Rendering Strategy

| Page | Strategy | Reason |
|------|---------|--------|
| Landing / Marketing | **Static (SSG)** | No dynamic data; best performance |
| Question Bank browse | **SSR** | SEO-critical; dynamic filters; cached 5 min |
| Question detail | **SSR** | SEO-critical; revalidate on content change |
| Candidate Dashboard | **Client (CSR)** | Real-time data; user-specific; no SEO value |
| Mock Interview session | **Client (CSR)** | Requires camera/mic; interactive; no SSR |
| Score Report | **SSR + client hydration** | Shareable URL; dynamic score data |
| Admin pages | **Client (CSR)** | No SEO value; highly interactive tables |

### Pre-Session Compatibility Check

```
1. Check navigator.mediaDevices.getUserMedia support
2. Check MediaRecorder.isTypeSupported() for video formats
3. Check camera + microphone permissions
4. If any fail → show diagnostic screen with browser recommendation
5. If all pass → show consent dialog → start session
```

## 7. Performance Strategy

| Technique | Applied To | Target |
|-----------|-----------|--------|
| React Server Components | Question Bank, Playbooks, Score Report (static parts) | Reduce JS bundle |
| Dynamic imports | Session recording UI, WebRTC client, Score charts | Load only when needed |
| Image optimization | Expert avatars, playbook thumbnails | `<Image>` with lazy loading |
| Prefetching | Question detail pages on hover | `<Link prefetch>` |
| Search debounce | Search input | 300ms debounce before API call |
| SWR cache (TanStack) | Question Bank, Archive | 5-min stale-while-revalidate |
| Service Worker (PWA) | Question Bank, Playbooks | Offline cache via `next-pwa` |

Lighthouse target: **Performance ≥ 90** on Question Bank and Dashboard pages.

## 8. WCAG 2.1 AA Implementation Patterns

| Pattern | Implementation |
|---------|--------------|
| Focus management | After modal opens → focus first interactive element; after close → return focus to trigger |
| Skip link | `<a href="#main-content" className="sr-only focus:not-sr-only">` at top of every page |
| Live regions | `role="status"` for score-ready notifications; `aria-live="polite"` for search results count |
| Form errors | `aria-describedby` links input to error message; `aria-invalid="true"` on invalid inputs |
| Session timer | Timer announces remaining time at 5min, 2min, 1min via `aria-live="assertive"` |
| Video captions | All embedded tutorial videos use `<track kind="captions">` |
| Color contrast | Minimum 4.5:1 ratio enforced via Tailwind config custom colors; verified with axe-core in CI |
| Icon buttons | All icon-only buttons have `aria-label`; `<Tooltip>` shown on hover/focus |
