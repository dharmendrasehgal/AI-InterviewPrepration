## What's New

Phase 2 expands the platform from AI-only practice into a full **human mentorship marketplace** — connecting candidates with verified industry experts for live 1-on-1 mock interview sessions, expert-written rubric evaluations, and structured industry playbooks.

### Expert Marketplace

Browse a curated directory of verified expert mentors. Filter by industry, career track, expertise level, and price. Every expert profile shows their background, session ratings, and available time slots. Booking a session takes under 2 minutes.

**What you get:**
- 50+ verified expert mentors at launch across software engineering, general career, and medical / residency tracks
- Expert profiles with background, session history, and candidate ratings
- Real-time availability calendar with timezone support
- Instant booking confirmation and calendar invite

### Live Mock Interview via Browser

Meet your expert directly in your browser — no download, no app installation. The interview is conducted over an encrypted WebRTC video connection with the same recording and consent flow as AI sessions.

**What you get:**
- Browser-based video and audio (Chrome, Firefox, Edge — no plugin required)
- Recording consent logged with timestamp before session begins
- Session recording archived in your Feedback Archive post-session
- Automatic fallback to audio-only if camera is unavailable

### Expert Rubric Evaluations

After each live session, your expert completes a structured rubric form rating you across key competency dimensions: communication clarity, technical depth, structured thinking, and confidence. You receive the rubric within 24 hours of your session, alongside improvement tips written specifically for you.

### Session Booking & Notifications

- Book, reschedule, or cancel sessions from your dashboard
- Automated reminders: 24 hours before and 30 minutes before your session
- Expert cancellations trigger automatic rescheduling prompts and refund initiation

### Industry Playbooks

Structured preparation guides written by industry professionals for three career tracks:

| Track | Sections |
|-------|---------|
| General Career | Interview fundamentals, STAR method, salary negotiation |
| Software Engineering | System design, algorithms, behavioural at tech companies |
| Medical / Residency | MMI stations, ethical scenarios, clinical case structure |

Each playbook includes question banks, sample answers, self-assessment checklists, and recommended session sequences.

### Self-Practice Record & Review

Can't afford a session yet, or just want to warm up? Use the Self-Practice tool to record a response to any question in the question bank privately. Responses are not sent to AI scoring — they are stored locally for your personal review. Delete at any time.

## Security & Privacy

- All live session video is encrypted in transit (DTLS-SRTP) and at rest (AES-256).
- Recording consent for live sessions is required and logged identically to AI sessions.
- Expert personal data follows the same AES-256-GCM at-rest encryption as candidate PII.
- Session booking data is not sold or shared with third parties.

## Bug Fixes (since v1.0.0)

- Fixed: `POST /api/v1/mock-sessions` returned HTTP 500 on valid requests due to unhandled database error (API-001)
- Fixed: `POST /api/v1/questions/:id/bookmark` returned HTTP 400 when client sent empty JSON body — Fastify body parsing now optional on this route (API-002)
- Fixed: `POST /api/v1/auth/logout` returned HTTP 400 when client sent empty JSON body — same fix as API-002 applied to logout route (API-003)
- Fixed: `ioredis` standalone package removed from `package.json` dependencies — BullMQ's bundled ioredis is used exclusively per architecture decision DEF-BullMQ
- Fixed: `access_token` was stored in `localStorage` in the frontend API client — token is now stored in Zustand memory only, never persisted to browser storage (DEF-001)
- Fixed: `docker-compose.yml` hardcoded `POSTGRES_PASSWORD` — now uses `${POSTGRES_PASSWORD:-app_password}` pattern (DEF-003)

## Upgrade Notes

### From v1.0.0 to v1.1.0

**Backend:**

1. Run the new Phase 2 database migrations:
   ```bash
   npm run db:migrate
   ```
   New tables created: `experts`, `expert_availability`, `bookings`, `expert_sessions`, `playbooks`, `rubric_evaluations`

2. Add new required environment variables (see `.env.example`):
   - `TURN_SERVER_URL` — TURN server URL for WebRTC NAT traversal
   - `TURN_SERVER_USERNAME` — TURN credentials username
   - `TURN_SERVER_CREDENTIAL` — TURN credentials password
   - `NOTIFICATION_PROVIDER` — email provider key (`sendgrid` or `ses`)

3. Update Redis connection — no BullMQ queue name changes; existing `scoring` queue is unchanged.

**Frontend:**

1. Clear any cached `access_token` from localStorage on your staging/production environment after deploying (DEF-001 fix). Existing sessions will be invalidated gracefully — users re-authenticate via the refresh cookie flow.

2. New pages added under `/experts`, `/book`, and `/playbooks` routes — no existing routes changed.

**No breaking API changes.** All Phase 1 endpoints (`/auth`, `/users`, `/questions`, `/mock-sessions`, `/feedback`) are unchanged.
