## Database Schema — Phase 2 New Tables

### `experts`

```sql
CREATE TABLE experts (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,
  bio_encrypted TEXT NOT NULL,                   -- AES-256-GCM encrypted
  headline      TEXT NOT NULL,
  industry      TEXT NOT NULL,
  track         TEXT NOT NULL,                   -- 'general_career' | 'software_engineering' | 'medical'
  years_exp     SMALLINT NOT NULL,
  rate_cents    INTEGER NOT NULL DEFAULT 0,      -- USD cents per 50-min session
  status        TEXT NOT NULL DEFAULT 'pending', -- 'pending' | 'approved' | 'suspended'
  approved_at   TIMESTAMPTZ,
  approved_by   UUID REFERENCES users(id),
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX experts_status_track_idx ON experts(status, track);
```

### `expert_availability`

```sql
CREATE TABLE expert_availability (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  expert_id   UUID NOT NULL REFERENCES experts(id) ON DELETE CASCADE,
  start_at    TIMESTAMPTZ NOT NULL,
  end_at      TIMESTAMPTZ NOT NULL,
  is_booked   BOOLEAN NOT NULL DEFAULT false,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT no_overlap EXCLUDE USING gist (
    expert_id WITH =,
    tstzrange(start_at, end_at) WITH &&
  )
);
CREATE INDEX expert_avail_expert_start_idx ON expert_availability(expert_id, start_at);
```

### `bookings`

```sql
CREATE TABLE bookings (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  candidate_id     UUID NOT NULL REFERENCES users(id),
  expert_id        UUID NOT NULL REFERENCES experts(id),
  availability_id  UUID NOT NULL UNIQUE REFERENCES expert_availability(id),
  status           TEXT NOT NULL DEFAULT 'confirmed',  -- 'confirmed' | 'cancelled' | 'completed' | 'no_show'
  cancelled_by     UUID REFERENCES users(id),
  cancel_reason    TEXT,
  created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX bookings_candidate_idx ON bookings(candidate_id);
CREATE INDEX bookings_expert_idx ON bookings(expert_id);
```

### `expert_sessions`

```sql
CREATE TABLE expert_sessions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  booking_id      UUID NOT NULL UNIQUE REFERENCES bookings(id),
  recording_key   TEXT,                          -- S3 key; NULL until upload complete
  transcript      TEXT,
  consent_at      TIMESTAMPTZ,
  started_at      TIMESTAMPTZ,
  ended_at        TIMESTAMPTZ,
  status          TEXT NOT NULL DEFAULT 'pending',  -- 'pending' | 'in_progress' | 'completed' | 'failed'
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### `rubric_evaluations`

```sql
CREATE TABLE rubric_evaluations (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  expert_session_id   UUID NOT NULL UNIQUE REFERENCES expert_sessions(id),
  expert_id           UUID NOT NULL REFERENCES experts(id),
  communication       SMALLINT NOT NULL CHECK (communication BETWEEN 1 AND 5),
  technical_depth     SMALLINT NOT NULL CHECK (technical_depth BETWEEN 1 AND 5),
  structured_thinking SMALLINT NOT NULL CHECK (structured_thinking BETWEEN 1 AND 5),
  confidence          SMALLINT NOT NULL CHECK (confidence BETWEEN 1 AND 5),
  overall_score       NUMERIC(3,1) GENERATED ALWAYS AS (
    (communication + technical_depth + structured_thinking + confidence) / 4.0
  ) STORED,
  notes_encrypted     TEXT,                      -- expert's private notes — AES-256-GCM
  feedback_text       TEXT NOT NULL,
  submitted_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### `playbooks`

```sql
CREATE TABLE playbooks (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  track       TEXT NOT NULL UNIQUE,              -- 'general_career' | 'software_engineering' | 'medical'
  title       TEXT NOT NULL,
  content     JSONB NOT NULL,                    -- structured sections as JSON
  version     INTEGER NOT NULL DEFAULT 1,
  published   BOOLEAN NOT NULL DEFAULT false,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### WebRTC Signaling Server

Phase 2 requires a lightweight WebSocket signaling server for ICE candidate exchange and session description protocol (SDP) offer/answer. Options:

**Option A (Recommended):** Add a `signaling-server.ts` entry point to the existing backend using Fastify's `@fastify/websocket` plugin. Register it under `wss://api.platform.com/api/v1/signaling/:sessionId`. Authenticate using the existing access token (Bearer in query param for WebSocket upgrade).

**Option B:** Separate microservice. Higher operational complexity — deferred unless Option A proves insufficient at scale.

Architecture decision required from `senior_architect_agent` before implementation begins.

### Notification Service (Phase 2 activation)

`modules/notification/email.service.ts` is currently a stub. Phase 2 requires a real provider. Activate one of:
- SendGrid (`@sendgrid/mail`)
- AWS SES (`@aws-sdk/client-ses`)
- Resend (`resend`)

Provider selection is an open question (per DECISIONS.md). Add `NOTIFICATION_PROVIDER` env var and implement an adapter pattern so the provider can be swapped without changing call sites.

Events to handle:
- `booking.confirmed` → candidate + expert email
- `booking.reminder_24h` → BullMQ delayed job
- `booking.reminder_30min` → BullMQ delayed job
- `booking.cancelled` → candidate + expert email
- `session.complete` → candidate email with rubric availability status
